BSB multilingual implementation rules

Go/Rust event filters are evaluated in configured alias sort order, first match wins. Missing/null filter accepts every operation; [] accepts none. Operation arrays, boolean maps, plugin lists and {enabled,plugins} entries are supported. Host appends an unfiltered local backend when none is configured. Place a catch-all after selective aliases. Malformed filters fail startup.
Registry implementation discovery returns only org/name/language/version summaries; fetch schemas/docs separately. Client installation rejects generated-name collisions before writing snapshots. .NET preserves UInt64 wire values, but AnyVali C# 1.1.1 uint64 validation remains capped at long.MaxValue.

RUST HOST / CLIENT TOOLING (2026-09-06)
- Rust 1.95+; BSB owns main and lifecycle. Crates export register(&mut bsb::host::Registry)->bsb::Result<()>. Static Contract/Ordering plus factories; constructors never run during export. Custom configuration/event/observer factories are supported.
- bsb-plugin.json rust entries: {id, crate: dependency alias or current crate}. bsb plugin build links selected crates into lib/bsb and exports lib/schemas. Workspace Cargo dependencies and CARGO_TARGET_DIR are supported. No dynamic Rust ABI loading or runtime package downloads.
- Full AnyVali 1.1.1 documents import once per event facade. Normalize SDK aliases only at schema nodes; preserve defaults, literals, definitions and metadata. Fresh reference parse contexts prevent cross-request contamination.
- bsb client install/sync/publish uses the shared Registry or private --target Vault. Source identity/version stays in .bsb/schemas; generated Rust modules go to src/bsbclients. Add pub mod bsbclients. Never handwrite shared-service clients.
- Optional<T>::Missing distinguishes omission from Present(None). Objects/arrays/maps/enums/references use typed Rust; complex structural shapes use Value plus full runtime validation. Generated client events() handles streams; specific(id) selects an instance. Pass incoming Observable through nested calls.
- Native configuration: file/env/Vault/Google ADC. Enabled plugins must target rust. Vault cache is encrypted and bound to endpoint/key/language. Invalid/auth/wrong-language responses never fall back to cached config. Environment override paths are explicitly allowlisted.
- Native events-default/Rabbit use matching durable queues, confirmed replies before ack, bounded retry/buffering and opaque stream IDs. Rust AsyncRead supports cancellation. Receivers consume through EOF and propagate errors. Streams do not resume across disconnects.
- Nine native observable backends; Pino/Winston names select equivalent Rust formats. TLS verification, bounded exporters and redaction-before-interpolation are required. Histogram ceiling: count/sum and one aggregate bucket. Runtime options are documented in rust/README.md.
- Seven examples in rust/examples/native_plugins use generated portable contracts; BSB links the crate. Todo's JSON file has one process owner and its unauthenticated HTTP example defaults to localhost.
- Release workflow creates a Rust .crate/CLI artifact and versioned runtime images. Image stages run non-root with CA certificates. No crates.io publish is configured.

BSB is the executable host. Applications are plugins loaded by BSB. Referencing BSB as a dependency does not start an application.

Registry identity is org/name + implementation language + version. The same version can exist independently in nodejs, csharp, python, go, java and rust. Normalize dotnet to csharp. Language metadata support does not imply that every native runtime is implemented.

GET /plugins/:org/:name/implementations discovers accessible variants. Pass ?language=csharp (or another source language) on details, versions, schema and documentation reads. /types/:language selects the output type language; its query language selects the source implementation. Unqualified legacy reads prefer Node when present. Clients must ask for --source-language when more than one accessible implementation exists.

Node: bsb client install org/service-name --source-language csharp --version 1.2.3
The generated client remains TypeScript. Schemas save source identity/version separately from the wire plugin target. Regeneration must preserve complete AnyVali documents, including definitions, defaults, wrappers and sensitive metadata. Do not replace shared services with handwritten native clients.

Vault chooses the host language on each deployment profile. An application can contain profiles for different languages. Existing profiles/catalog records default to nodejs. Native catalog entries and publishing credentials are scoped by language. Enabled plugins must match the host language; disabled service references may point at a remote implementation. A published deployment profile cannot change its host language. Create another profile for a different host.

.NET contracts use AnyVali 1.1.1. BSB shares both BSB and AnyVali assemblies with dynamically loaded plugins. Declare static Metadata, ConfigSchema and EventSchemas on plugins. Use native AnyVali schemas or BSBTypes. Create generated clients in service constructors with the service Events context; BSB wires their backend before Init.

.NET config selection: BSB_CONFIG_PLUGIN=config-default|config-env|config-vault|config-vault-google. Optional BSB_CONFIG_PLUGIN_PACKAGE selects an external package. Config providers use the same lower camel case Vault settings as Node: vaultUrl, apiKeyId, apiSecret, timeoutMs, staleAllowedHours, cacheDir, allowInsecureHttp, googleAudience. Never log credentials.

Native Vault startup must reject wrong-language responses, auth failures, redirects and invalid schemas. Cache only validated responses, encrypted and bound to origin/key/language. Apply BSB_CONFIG_OVERRIDES in memory only, restricted to envOverridePaths returned by Vault. Cache formats are runtime-specific; do not share cache files between languages.

See dotnet/README.md for current implemented native features and CLI commands. Do not claim Go/Rust host support from registry enum values alone.

Go/Rust native hosts, tooling, backends and examples are implemented; see docs/native-go-rust-plan.md, go/README.md and rust/README.md. Go plugins register factories and static PluginContract schemas. The host validates registered config schemas before construction and wires event schemas into service facades. Go file/env/Vault providers share profile validation; only enabled plugins must match go, while disabled references may target remote languages. The Go Rabbit implementation uses the same durable queues and stream envelopes, with producer/consumer declarations and confirmed replies before ack. Go/Rust packages are linked into a BSB-owned executable at build time; remote profiles never install or execute unapproved packages. Do not claim full parity until tooling, native observability and real integration gates pass.

.NET generated optional properties use OptionalValue<T>. Unset means omitted; OptionalValue<string?>(null) means present null. Do not collapse these states when generating clients. Specific(serverId, ...) methods append Node's event-serverId suffix while validating the unsuffixed contract.

.NET RabbitMQ uses Node BSB 9 queue names and {trace:{t,s},args:[payload]} envelopes. Keep durable fire/RPC queues for missing listeners. Confirm replies before acknowledging requests; failed publishes must redeliver. Handlers must tolerate duplicate execution. Ten poison attempts dead-letter. Stream receivers register a callback and return an opaque ID; pass that ID to the sender. The old ReceiveStream/SendStream overloads without an ID only work locally.

.NET file/Pino/Winston logging uses native options documented in dotnet/README.md. Do not copy JavaScript transport modules into native configs. Optional file logging supports size/time rotation, gzip, retention and dotted/wildcard redaction. Pino/Winston are native equivalents.

.NET remote plugins: observable-opentelemetry (OTLP HTTP JSON), observable-axiom (dataset ingestion and OTLP traces), observable-zipkin (v2 traces), observable-graylog (GELF UDP/TCP/TLS/HTTP), observable-syslog (RFC 5424/3164 UDP/TCP/TLS). Use each native ConfigSchema; Node option layouts are not interchangeable. Buffers are bounded and non-durable. Keep TLS hostname/chain validation, no credential-bearing redirects, no retry of partial acknowledgements. Metrics have per-plugin namespaces; native recording overrides receive pluginName first.

.NET packages: BetterCorp.BSB SDK; BetterCorp.BSB.Cli tool, command bsb. bsb plugin pack <project.csproj> includes BSB metadata in NuGet. bsb plugin install <package> --version <exact-major.minor.patch> [--source <feed>] atomically installs .bsb/plugins/<package>/<version>; BSB_PLUGIN_DIR overrides the root. Configure logical plugin ID separately from NuGet package and assembly. Runtime-only images load prebuilt plugins; tooling requires an SDK build stage. Never construct application services during schema export.

Lifecycle ordering resolves explicit profile aliases before logical metadata names. Logical names match every configured instance; cycles must fail, including a single plugin referencing itself. Real broker integration passes all 20 Node/.NET/Python/Go/Rust RPC/trace/stream directions and crashed consumers. PostgreSQL migration CI passed at 017b1b9.

The native-integration CI job runs tests/integration/rabbit_languages.py against RabbitMQ and vault-postgres.mjs against PostgreSQL. These require real services; adding the job does not mean it has run. Local fast suites remain separate.

Registry HTTP uses rateLimitMax (default 300 requests per peer IP per minute per instance) before authentication. Health checks are exempt; forwarded IP headers are not trusted. Configure gateway limits for individual clients behind a reverse proxy and a shared budget across replicas.

Vault shared application-profile publication validates each active deployment's effective configuration and host language. Disabled remote references retain their implementation language. Native AnyVali wrappers may use schema/inner and unions schemas/variants. Keep secret detection shared between server and browser. Sensitive collections and referenced schemas use write-only whole-value JSON replacement; omission preserves the existing value. Do not restore secrets by array index after a reorder.

Python: BSB is the host (`bsb run`), applications are standard wheels with [project.entry-points."bsb.plugins"] mapping logical IDs to module:Class. Export Config.metadata, Config.validation_schema and Plugin.EventSchemas. No application constructors during plugin build/export. Create generated clients in constructors; register listeners in init. Use async dispose for cleanup. One installed distribution version per virtual environment; separate hosts for conflicting dependency versions. bsb plugin pack builds a wheel; bsb plugin install accepts a wheel or distribution --version. BSB_PLUGIN_DIR and safe local manifests support development sources.

Python plugin versions accept exact semantic prerelease/build suffixes. Wheel versions must also be PEP 440-compatible: profile 1.2.3-beta.1 matches installed distribution 1.2.3b1 through packaging.version normalization. Keep the original exact Registry version in identities and client snapshots.

Python clients: bsb client install org/service --source-language nodejs --version 1.2.3. Save full documents in .bsb/schemas/org~name~language.json; preserve wire pluginId separately. Generate Python TypedDict/NotRequired/Literal/union/tuple types and runtime AnyVali validation. Configure [tool.bsb] clients-package="my_package.clients" for reusable plugin distributions. Never handwrite Registry/Vault/syslog-specific clients. Native av.object_ requires an explicit required list for optional properties; bsb.schema.object_schema infers it. Required object sections without object-level defaults must be supplied, even if all their children have defaults.

Python config-default/env/Vault/VaultGoogle, events-default/Rabbit, and native observability plugins are implemented; see python/README.md for options. AnyVali 1.1.1 uses schema/inner and elements/items aliases across SDKs. Keep full definitions, constraints, metadata and optional-vs-null semantics. Python Rabbit uses the same durable queues, confirmed replies, redelivery and opaque stream IDs as Node/.NET. Stream timeout IDs use whole seconds. Poison counts are local to a consumer process. Recovery restores topology on the selected endpoint; streams do not resume across failures.

Python observability: file/Pino/Winston are native equivalents, not JS adapters. OTLP HTTP JSON/Axiom/Zipkin and GELF/syslog share bounded asynchronous exporting, TLS verification, redaction and shutdown draining. Metrics are cumulative and namespaced per plugin. Buffers are non-durable. Native examples live in python/examples/native_plugins; generic generated clients share Node contracts. The todo HTTP server and JSON storage are examples, not a production multi-writer persistence layer.
